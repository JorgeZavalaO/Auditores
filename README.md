# Auditores landing

Static, responsive Astro landing for a Peruvian accounting and auditing firm. The Spanish content is based on the supplied company document. The name **Auditores** and its monogram are provisional, not an approved commercial identity.

## Local development

Requires Node.js 22.12 or newer (implemented and verified with Node 24).

```sh
npm install
npm run dev
```

Open the localhost URL printed by Astro. The project builds as static HTML; only the mobile navigation and the demo form use JavaScript. Images are local, responsive WebP files generated by Astro, and Manrope is self-hosted.

## Design demonstrations

- `/`: the original landing, unchanged in composition and content.
- `/demo1/`: the original landing composition and services, rendered from the shared `DemoOneLanding.astro` component with the confirmed **J&J CONSULTORES Y AUDITORES** header/footer and metadata.
- `/demo2/`: a distinct corporate proposal for medium and large enterprises, centered on financial/tax auditing and internal controls, now using the same confirmed J&J identity. This is new positioning, not a claim about existing large-company clients or credentials.
- `/demo3/`: a branded editorial direction for **J&J CONSULTORES Y AUDITORES**, with ivory/navy surfaces, serif typography, an illustrative review diagram and brief progressive motion. Its content, appearance and interactions are unchanged by the demo1/demo2 branding update.

The corporate demo uses separate content in `src/data/corporate.ts`, a `CorporateLanding.astro` composition and a `CorporateContact.astro` local-only form. Its component-scoped styles do not change the original landing. All demos use the confirmed J&J identity with visibly marked example contacts. Optional branded Header/Footer props retain historical defaults for `/`; the global company data and original root identity remain unchanged until final promotion is separately authorized.

**All demo routes and their subpages always remain `noindex, nofollow`**, including launch-ready builds. They have no canonical, business schema or social page URL, and their entire subtrees are excluded from the sitemap. Only `/` may become indexable. Production robots continues to allow crawling so search engines can read the demo pages' noindex directives; this is not a privacy or access-control feature. Do not remove these protections or publish multiple competing versions as indexable commercial pages.

Demo3 uses `src/data/editorial.ts`, `EditorialLanding.astro` and the reusable `JJBrand.astro` wordmark shared by all three demos. Its serif is the system Georgia font, without a new network font or animation dependency. The wordmark/favicon are design treatments of the confirmed name, not a claim of trademark registration. The audit diagram is explicitly illustrative, not an actual client report or financial result. The safe `CorporateContact.astro` preserves historical defaults through optional configuration props.

Motion is optional enhancement: all source HTML is visible before or without JavaScript. IntersectionObserver adds one 650ms transform/opacity entrance to non-critical sections, and a decorative scan runs once for 1900ms. The H1, main image and form are never reveal targets. CSS and runtime respect `prefers-reduced-motion`, including preference changes; unsupported browser APIs fall back to static content. No flashing, parallax, perpetual animations, autoplay or animated business metrics are used. Tests cover static/API fallbacks, one-shot behavior and reduced-motion changes; browser verification remains necessary for the actual appearance.
If the browser or operating system requests reduced motion, this preview intentionally stays static. Do not override that preference simply to demonstrate an animation.

## SEO strategy

One commercial route avoids unnecessary competing service pages. Each secondary intent has a distinct section on the same page; repeated keywords are not used to manufacture extra pages.

| Intent | Placement |
| --- | --- |
| Auditoría y asesoría contable para MYPES en Perú | Page title, description, opening copy |
| Outsourcing contable y financiero | Services section |
| Auditoría financiera y tributaria | Services section |
| Gestión laboral y planillas | Services section |
| Diagnóstico contable y tributario gratuito | Conversion section and contact |
| Regularización, control interno and ERP | Supporting services |

There is one H1, a semantic heading hierarchy, accessible anchor navigation, descriptive image alternatives, an explicit page language and static source-readable content. Structured data describes actual service categories without fabricated reviews, contacts, locations or credentials. This is a technical and content foundation, not a guarantee of rankings. Any future service page should have a distinct user need, substantial unique content and a non-overlapping target intent.

## Publication checklist

1. The commercial name **J&J CONSULTORES Y AUDITORES** is confirmed; its visual wordmark may still need design approval. The historical root and its schema intentionally retain the earlier **Auditores** identity to preserve the comparison versions.
2. Obtain approval for the final composition, then implement its promotion to `/` and update `src/data/site.ts`, the root title/description and structured-data identity to the confirmed J&J name. This promotion has not been authorized or performed. Enabling the launch flag does **not** promote demo3: `/demo1/`, `/demo2/` and `/demo3/` remain permanently non-indexable.
3. Replace the example contact details in `src/data/site.ts`; set `contactIsExample` to `false` after replacing the copy. Review the utility bar, contact section and footer to remove preview labels only when appropriate. Contact links are intentionally absent; add them only for verified real channels.
4. Verify client-logo publication permission, the legal company name and the partners' experience claim. No credentials, testimonials or business address were invented.
5. Configure and test real form delivery, then provide the corresponding privacy information.
6. Copy `.env.example` to `.env`; set `SITE_URL` to the real HTTP(S) public origin with no path, credentials, query or fragment. Domain syntax is validated, not ownership or DNS.
7. Set `PUBLIC_LAUNCH_READY=true` **only after the final root composition, J&J identity migration, business information and launch checklist are approved and implemented**. Supplying a domain alone never enables indexing.
8. Run check, build, tests, desktop/mobile review and the real contact-flow verification. Test the deployed domain and submit its sitemap through the business's search-console account after deployment is authorized.

Default preview output uses `noindex, nofollow`, `robots.txt` with `Disallow: /`, and no canonical, sitemap or business schema. Configured launch output enables indexing, a canonical and social URLs from the same origin, a sitemap and `ProfessionalService` structured data. `robots.txt` is a crawler policy, not an access-control mechanism. The launch flag is a deliberate release decision and does not automatically verify the business facts, contact delivery or domain ownership.

No analytics, remote font calls, tracking cookies or unnecessary cookie banner are included. Deployment, an actual domain, form delivery and search-console integration were not requested or performed.
